# Accessibility: WCAG conformance and inclusive interaction (platform-agnostic)

## Folk-rule guards

- **"44x44 is the universal touch target."** Wrong as a single constant. iOS uses 44x44pt, Android uses 48x48dp, and WCAG 2.2's web/hybrid target-size criteria (T03) are a separate, CSS-pixel-based bar — see `mobile.md` for the platform-specific numbers. Never apply one number across all three.
- **"Disabled buttons are bad."** A disabled control can be valid accessibility-wise as long as: (a) it still exposes a correct accessible name/role/state (X01) rather than disappearing from the accessibility tree, and (b) the unmet prerequisite is understandable to the user, not just a dead end.

## How the accessibility skill should apply these

Always identify target platform(s) before scoring a target-size or text-scaling finding (X04/X05/T01/T02 live in `mobile.md`) — the correct minimum differs by platform, and applying iOS's 44pt to an Android screen (or vice versa) is itself a wrong finding. WCAG-sourced rules (X01-X03, X06-X14, T03-T05) apply regardless of platform and should be checked first since several carry Blocker severity. When evidence is a static screenshot or mockup, most of this file's rules are only partially assessable — contrast (X03), color-alone cues (X02), and instructional/action-verb wording (X13-X14) can be checked from a static image or copy alone, but reading order (X01), focus visibility (X08), and gesture-only functionality (X06, T05) usually require a running build or code; report accordingly using the evidence model.

Check X15 whenever the evidence indicates or implies the product's real-world user base spans varied hardware tiers or connectivity conditions (a consumer app, a public-sector or widely-used service) — this is a distinct inclusive-design axis from X01-X14's disability-focused WCAG conformance, so a product can fully pass WCAG while still failing X15's equitable-access concern. Do not apply X15 to a specialized enterprise/professional tool whose evidence establishes a legitimate minimum hardware/connectivity requirement for its verified audience.

Check X17 whenever the evidence shows a tooltip, submenu, or clickability cue that appears on mouse-hover; most of X17-X22 require code, a design spec, or a described DOM/markup structure rather than a rendered screenshot alone, and should be reported `NOT ASSESSABLE` when only a static visual is available — consistent with how X01 (reading/focus order) is already treated. Check X18 whenever the evidence includes link styling (code or a design spec stating link colors) for whether visited and unvisited states remain distinct. Check X19 whenever the evidence includes a list of links or headings, regardless of whether the surrounding content is short native UI copy or long-form body text — X19 applies to link/heading lists specifically, unlike `product`'s C07/C08 which are scoped to long-form content only. Check X20 whenever the evidence shows or describes a page with persistent header navigation, for a skip-to-content link as the first focusable element. Check X21 whenever the evidence exposes heading markup, for an unskipped, structurally-accurate heading hierarchy. Check X22 whenever the evidence exposes image markup, for alt text matching each image's informative-vs-decorative role. X23 is a markup-level check and X24 is a contextual comfort check: report X23 as `NOT ASSESSABLE` from a screenshot, and never let X24 lower a text pairing below the X03 contrast floor.

Check X25 whenever text or an informative icon sits on a photograph, gradient or video frame: test the worst-case region of the image, not the average. A fixed scrim that holds the ratio passes; a user-supplied image with no scrim is a risk even when the sample image passes.

Baymard Institute research rules added in this file: X27, X28. Check each when the evidence shows its surface (forms and checkout, navigation, search and filters, accounts and orders, delivery and returns); each reports `NOT ASSESSABLE` for parts the evidence does not show.

Nielsen Norman Group research rules added in this file: X29, X30, X31, X32, X33, X34. Check each when the evidence shows its surface; each reports `NOT ASSESSABLE` for parts the evidence does not show.
